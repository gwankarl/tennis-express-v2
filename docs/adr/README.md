# Architecture Decision Records

Create an ADR when a significant technical decision needs its own durable record.

Each ADR should include:

- Number and title
- Status: Proposed, Accepted, Superseded or Rejected
- Context and problem
- Decision
- Alternatives considered
- Consequences and trade-offs
- Date and related decisions

Do not duplicate every entry from the project decision log as an ADR. Use ADRs for
decisions whose technical context and consequences deserve a dedicated explanation.
